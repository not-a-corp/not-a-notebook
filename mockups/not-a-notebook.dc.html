not-a-notebook — interface mockups1440 × 900 · Light, Dark, Catppuccin Mocha · from design.md
Home. The background is static in the mocks; the slow drift is left to the build. The composer shows focus with a caret only, no ring. Send turns on as soon as a file is attached, because a file can be sent with no question.
Drag over home. A dashed outline inset 12 px, a tint and a “Drop to attach” label set above the composer so the composer stays readable underneath.
Pane tabs. A 36 px tab strip on each pane. Maximise sits at the right end of the strip. The cell count is the real one: 3 cells mid-run, 5 when finished (your example said 4).
Swap and resize. The pane under the drag also gets a “Drop to swap panes” label, which I added. 4d shows the divider on hover: a 13 × 32 grip and a darker line.
Settings. A back arrow in a 48 px header, the 200 px nav, then sections capped at 760 px. The sidebar gear is now labelled Settings.
Theme cards. The selected card matches the frame’s theme: Light in 7a, Dark in 7b, Mocha in 7c. A light page with Mocha selected can’t happen. The Mocha colour-blindness trade-off is a line under the cards rather than a tooltip, so it can be read in the mock.
Models at 760 px. Source sits under the name and the key under the model. Test results go on their own line under each row so the failure message isn’t cramped.
Split and activity. 40/60, no files column. The activity line stays inside the analyst’s message, as written. Failed attempts are a collapsed row inside the cell.
Findings count. The brief says “4 findings” but lists five for relatorio.csv. I used 5 everywhere.
Syntax colours. Light/Dark: keywords violet, strings ochre, numbers orange, function names in the accent colour. Mocha uses Catppuccin’s mapping.
Placeholders. The wordmark is lowercase JetBrains Mono; the Google mark is a placeholder. The mocks load the fonts from Google Fonts, but the app ships them.
Charts. Drawn statically to §5.4. The build renders them with plotly.
